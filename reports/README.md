# Reports — تقارير أمنية

هذا المجلد مخصّص لتقارير مراجعة الكود والفحص الأمني، بعد إكمال مسار PortSwigger.

## قالب التقرير المقترح

```md
# تقرير مراجعة أمنية — [اسم المشروع]

**التاريخ:** YYYY-MM-DD
**النطاق:** [المستودع / الخدمة / الـEndpoints]
**المنهجية:** Secure Code Review + Dynamic Testing

## ١. الملخص التنفيذي
- إجمالي النتائج: X
- حرجة: X | عالية: X | متوسطة: X | منخفضة: X

## ٢. النتائج

### [AC-01] مثال: IDOR في /api/accounts/{id}
| | |
|---|---|
| **الخطورة** | High |
| **CWE** | CWE-639 |
| **الموقع** | `AccountController.java:42` |
| **الأثر** | قراءة بيانات أي مستخدم |

**الوصف:** ...
**إثبات المفهوم:** ...
**الإصلاح المقترح:** ...
**المرجع:** ...

## ٣. ملحق الأدلة
- طلبات/استجابات Burp
- مقاطع كود
```

## قواعد كتابة التقرير

- ابدأ بالأثر على العمل، ثم التفاصيل التقنية.
- كل نتيجة يجب أن تحتوي **إثبات مفهوم** و**إصلاحًا محددًا**.
- لا تضع بيانات اعتماد حقيقية في التقرير.
- اربط كل نتيجة بـCWE ومرجع (OWASP / PortSwigger).
